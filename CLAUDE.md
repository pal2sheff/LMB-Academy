# LMB Академия

## Цель

Продолжить разработку внутренней учебной базы клиники Love my body по `LMB_TZ.md`. Исходный прототип находится в `site/`. Это экспорт для разработки; автоматическое размещение на новой площадке не требуется.

## Постоянные правила

- Сохранить 14 исходных направлений, их порядок в `content/modules.json` и постоянные ID (исходник — `legacy/prototype-1bdedd4/modules.json`). 15-е направление `steroid-saliva` добавлено в конец. Показ на сайте — по трём группам (`category`) и `displayOrder` внутри группы; иконки — только встроенный набор `iconPaths` в `site/app.js`.
- Редакторские разделы саммари (что дополнить, какие материалы нужны) не удаляются из Markdown, а перечисляются в `editorialSections` и исключаются из учебного представления при сборке.
- На сайте публикуются саммари. Полные лекции, сканы и рабочие расшифровки отдельно.
- Сначала врачебный материал; административная версия создаётся из конкретной утверждённой врачебной версии.
- В исходнике шесть предварительных саммари и восемь структур. Переносить медицинские тексты как черновики, без выдуманной отметки об утверждении.
- Основной процесс: содержание готовится в ChatGPT с главным врачом, Claude Code подключает готовые пакеты и развивает сайт.
- Не менять медицинский смысл при технической интеграции. Несоответствия фиксировать для редактора.
- Не выдумывать источники, показания, дозы, настройки, референсы и подписи рецензентов.
- Не использовать индивидуальные документы пациентов как содержимое учебного сайта.
- Сохранять прослеживаемость существенных утверждений до источника, страницы, слайда или времени.
- Не терять существующие тексты, источники и маршруты при доработке.
- Сначала аудит текущего HTML/CSS/JS. Смена фреймворка должна иметь обоснование.
- Числа в интерфейсе вычислять из данных.
- Переключение варианта обучения не является авторизацией.
- Закрытый репозиторий сам по себе не гарантирует закрытого сайта.
- `private/`, черновой предпросмотр, токены и исходные медицинские документы не должны попадать в сборку сайта.
- Не подключать внешние ИИ-API и платные услуги без отдельного задания.
- Техническую работу продолжать при отсутствии медицинских исходников, обозначая нехватку по темам.
- В учебном интерфейсе нет лозунгов, статистики разработки, объяснений внутреннего процесса и лишнего декора. Пользователь сразу находит направление и читает материал. Пояснения для редакторов — в `docs/`. Метка «Черновик» на неутверждённом материале обязательна.

## Начало работы

Прочитать `START.md`, `LMB_TZ.md`, `BASELINE.md`. Проверить доступные команды и зависимости; в комплекте нет готового нового конвейера сборки. Не сообщать об успешной проверке или расшифровке, если она не выполнялась.

## Команды (реализовано, см. README.md)

- `python scripts/lmb.py check` — проверка контента; `status` — сводка.
- `python scripts/lmb.py preview` / `build` — предпросмотр с черновиками / рабочая сборка в `dist/`.
- `python -m unittest discover -s tests` — проверки по критериям приёмки.
- `approve` выполняет только редактор по решению ответственного врача; Claude Code её не запускает.
- Процесс наполнения: `docs/CONTENT_WORKFLOW.md`. Вопросы редактору: `docs/EDITORIAL_QUESTIONS.md`.

В финале каждого этапа сообщать: что изменено, что проверено, какие материалы нужны и что остаётся нерешённым. Конкретные команды запуска и проверки после реализации добавить в README.
