# LMB Академия

Внутренняя учебная база клиники Love my body: каталог из 15 направлений в трёх группах («Диагностика», «Вмешательства», «Основы и клинические направления»), саммари по темам в двух вариантах обучения («Врачам» и «Администраторам»), поиск, проверка утверждения и сборка без черновиков. Первоначальные 14 направлений из ТЗ сохранены с прежними ID; 15-е — «Стероидный профиль в слюне» (`steroid-saliva`).

Требования к проекту — [LMB_TZ.md](LMB_TZ.md). Правила для Claude Code — [CLAUDE.md](CLAUDE.md). Как добавлять и обновлять темы — [docs/CONTENT_WORKFLOW.md](docs/CONTENT_WORKFLOW.md).

## Что нужно для запуска

Только **Python 3.9 или новее**. Внешних зависимостей нет: инструменты используют стандартную библиотеку, поэтому файл фиксации зависимостей не нужен. Python выбран потому, что на рабочем компьютере нет Node.js, а для Markdown, проверки и локального сервера достаточно стандартной библиотеки.

Если Python установлен из Microsoft Store, держите проект вне `AppData` (например, в «Документах» или «Загрузках»).

## Команды

Все команды выполняются из корня проекта.

| Задача | Команда |
| --- | --- |
| Проверить контент | `python scripts/lmb.py check` (подробно: `check -v`) |
| Сводка по темам и статусам | `python scripts/lmb.py status` |
| Предпросмотр с черновиками | `python scripts/lmb.py preview`, затем `python scripts/lmb.py serve preview` → http://127.0.0.1:8000 |
| Рабочая сборка | `python scripts/lmb.py build` → папка `dist/` |
| Посмотреть рабочую сборку | `python scripts/lmb.py serve dist --port 8001` |
| Демонстрация учебного пакета (локально, не публикуется) | `python scripts/lmb.py demo`, затем `python scripts/lmb.py serve demo` |
| Однофайловая версия для закрытого просмотра | `python scripts/lmb.py bundle preview` → `bundle/lmb-academy-preview.html` |
| Новая тема | `python scripts/lmb.py new-lesson infusion infusion-vitamins --title "Витаминные инфузии"` |
| Контрольная сумма варианта | `python scripts/lmb.py checksum infusion-intro doctors` |
| Записать утверждение | `python scripts/lmb.py approve infusion-intro doctors --reviewer "ФИО" --date 2026-10-20` |
| Автоматические проверки | `python -m unittest discover -s tests -v` |
| Сверка перенесённых текстов с прототипом | `python scripts/migrate_legacy.py --verify` |

`approve` запускает редактор **только после решения ответственного врача**. Claude Code эту команду не выполняет и имён рецензентов не вписывает.

## Устройство

```text
content/modules.json                 направления: ID, номер, название, группа (category), порядок в группе (displayOrder), ключ иконки, описание, ключевые слова, темы
content/lessons/<id>/metadata.json   метаданные темы и обоих вариантов
content/lessons/<id>/doctors.md      врачебный текст (Markdown)
content/lessons/<id>/admins.md       выжимка для администраторов (появляется после утверждения врачебной версии)
content/lessons/<id>/history/        снимки утверждённых версий (создаёт approve)
content/sources/public.json          публичный реестр источников: название, автор, год, тип, внешняя ссылка
content/synonyms.json                словарь поисковых синонимов
site/                                интерфейс: index.html, app.js, styles.css (без медицинских текстов)
scripts/lmb.py                       проверка, сборка, предпросмотр, утверждение
scripts/migrate_legacy.py            однократный перенос текстов прототипа (сохранён для прослеживаемости)
templates/                           шаблоны приёма материалов, саммари, проверки и метаданных
tests/                               проверки по критериям приёмки
docs/                                процесс наполнения, аудит, план, недостающие материалы, вопросы редактору
legacy/prototype-1bdedd4/            неизменённый исходный прототип
private/                             исходники и рабочие файлы; не в Git и не в сборке
preview/, dist/                      результаты сборки; не хранятся в Git
```

Сборка копирует в `dist/` четыре файла (`index.html`, `app.js`, `styles.css`, `data.js`) и папку `media/` только с теми учебными иллюстрациями из `content/media/`, на которые ссылается публикуемая версия. Любой другой файл считается ошибкой. Учебный пакет темы описан в `templates/lesson_package/README.md`. Сайт открывается и с локального сервера, и двойным щелчком по `dist/index.html`.

### Что попадает в рабочую сборку

| Вариант темы | Предпросмотр | Рабочая сборка |
| --- | --- | --- |
| Саммари `approved` с действительной контрольной суммой | показывается | показывается, метка «Проверено» |
| Саммари в другом статусе | показывается с меткой «Черновик» | не попадает; если есть ранее утверждённая версия из `history/`, показывается она |
| Саммари `approved`, изменённое после утверждения | показывается | **сборка останавливается с ошибкой** |
| Программа раздела (`outline`) | показывается с меткой «Готовится» | то же |
| Нет текста | «Материал готовится» и запланированные разделы | то же |
| `withdrawn` или `archived` | «Недоступно» | то же, без текста |

Метка «Проверено» появляется только при действительной записи об утверждении этой версии (статус `approved`, совпадение версии и контрольной суммы). Интерфейс не объясняет посетителю внутренний процесс; эти правила описаны здесь и в `docs/CONTENT_WORKFLOW.md`.

## Размещение

Площадка не выбрана; публикация не настроена (ТЗ, раздел 12). На хостинг выкладывается только содержимое `dist/`. Закрытый репозиторий, скрытый адрес и переключатель «Для врачей / Для администраторов» доступ не ограничивают. Перед открытием доступа команде нужно без авторизации проверить, что недоступны страница, `data.js` и остальные файлы (критерий A15).
