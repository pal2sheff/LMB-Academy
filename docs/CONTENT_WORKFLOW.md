# Как добавлять и обновлять материалы

Интерфейс (`site/`) при работе с содержанием не редактируется. Все изменения вносятся в файлы `content/`.

Роли: **редактор** собирает и оформляет материал, **ответственный врач** (главный врач или назначенный им профильный врач) принимает медицинское решение. Claude Code подключает подготовленный пакет к сайту, не меняя медицинского смысла, и выписывает замеченные несоответствия в `docs/EDITORIAL_QUESTIONS.md`.

## 1. Приём пакета

1. Положить исходники в `private/inbox/<module-id>/<batch-id>/`, например `private/inbox/infusion/2026-10-20-lecture/`.
2. Заполнить карточку `templates/material_intake.md` и сохранить её в `private/editorial/<batch-id>.md`.
3. Записать каждый файл в `private/source-register.json` по образцу `templates/source-register.example.json`: ID, авторское название, автор, дата, редакция, SHA-256, роль, состояние. Контрольную сумму файла даёт PowerShell: `Get-FileHash <файл>`.

`private/` не попадает ни в Git, ни в сборку. Индивидуальные документы пациентов в учебный контент не включаются.

## 2. Новая тема

```bash
python scripts/lmb.py new-lesson infusion infusion-vitamins --title "Витаминные инфузии"
```

Команда создаёт `content/lessons/infusion-vitamins/` с `metadata.json` и `doctors.md` (разделы из шаблона `templates/doctor_summary.md`) и добавляет тему в конец списка `lessons` направления. Можно создать те же файлы вручную.

Далее:

1. Заменить текст в `doctors.md` готовым саммари. Разделы начинаются с `## `. Поддерживаются `###`, списки, таблицы, **жирный**, *курсив*, ссылки `https://…`, `lesson:<id>` и `module:<id>`. HTML в тексте не работает и выводится как текст.
2. В `metadata.json` → `variants.doctors` заполнить:
   - `goal` — краткая цель (для чего читать);
   - `takeaway` — ключевая мысль;
   - `scope` — короткая подпись объёма, например «Саммари СОП-12 и лекции 2026»;
   - `coverage` — что охвачено: `concept`, `safety`, `clinical`, `interpretation`;
   - `sources` — `[{"id": "…", "locator": "с. 12–14", "supports": "что подтверждает"}]`;
   - `claims` — существенные утверждения: `[{"id": "c1", "text": "…", "sourceId": "…", "locator": "слайд 8"}]`;
   - `program` — список тем, который показывается, пока саммари не утверждено;
   - `updatedAt` — дата редакции.
3. Новый источник добавить в `content/sources/public.json`. Допустимые поля: `id`, `title`, `author`, `year`, `type`, `url`, `note`. Внутренние пути и закрытые ссылки сюда не вносятся: для них есть `private/source-register.json`.
4. Проверить и посмотреть:

```bash
python scripts/lmb.py check
python scripts/lmb.py preview
python scripts/lmb.py serve preview
```

## 3. Статусы и версии

`editorialStatus`: `draft` → `needs_clarification` (есть вопросы к врачу) → `in_review` (на проверке) → `approved`. Статус `archived` снимает вариант с публикации.

Версия `MAJOR.MINOR.PATCH`:

- **PATCH** (1.0.0 → 1.0.1) — опечатка без изменения смысла. Отметки «Прочитано» сохраняются.
- **MINOR / MAJOR** — содержательное изменение. Сотрудники, отметившие прочтение, увидят «Обновлено».

Выбор между PATCH и MINOR — это и есть зафиксированное редакционное решение (ТЗ, шаг 8). Любое изменение текста или клинических метаданных требует нового утверждения, даже при PATCH.

## 4. Утверждение

1. Ответственный врач проверяет текст по карточке `templates/editorial_review.md` (хранится в `private/editorial/`).
2. После его решения редактор выполняет:

```bash
python scripts/lmb.py approve infusion-vitamins doctors --reviewer "ФИО врача" --date 2026-10-20
```

Команда ставит `editorialStatus: approved` и записывает `approval` (версия, контрольная сумма, рецензент, дата). Снимок текста сохраняется в `history/`.

Контрольная сумма охватывает Markdown и поля `title`, `version`, `contentKind`, `coverage`, `goal`, `takeaway`, `scope`, `sources`, `claims`, `derivedFrom`. Изменение хотя бы одного символа после утверждения делает запись недействительной, и `build` остановится с ошибкой. Рабочая сборка всё равно не опубликует неутверждённый текст.

## 5. Обновление существующей темы

1. Отредактировать `doctors.md` или метаданные.
2. Поднять `version` по правилу выше, поставить `editorialStatus: "in_review"`, `approval: null`, обновить `updatedAt`.
3. До утверждения новой редакции на сайте остаётся последняя утверждённая версия из `history/` с пометкой «новая редакция готовится».
4. После решения врача выполнить `approve`.

**Срочное снятие** по решению главного врача: добавить варианту поле `"withdrawn": {"date": "2026-10-20", "note": "Причина для сотрудников"}` и пересобрать. Текст исчезает со страницы и из поиска, предыдущие версии тоже не показываются.

## 6. Выжимка для администраторов

Начинается после утверждения врачебной версии темы.

1. Создать `admins.md` по шаблону `templates/admin_summary.md`.
2. В `variants.admins` указать `"contentKind": "summary"`, `"body": "admins.md"`, `version`, `goal`, `takeaway` и `derivedFrom`:

```json
"derivedFrom": {"lessonId": "infusion-vitamins", "variant": "doctors", "version": "1.0.0", "checksum": "sha256:…"}
```

`checksum` берётся из `approval.checksum` врачебной версии или командой `python scripts/lmb.py checksum infusion-vitamins doctors`.

3. Утвердить: `approve infusion-vitamins admins --reviewer "…"`. Команда откажет, если `derivedFrom` не указывает на утверждённую врачебную версию.

Когда врачебный текст меняется, `check` выдаёт «требуется сверка», а на странице выжимки появляется пометка. После сверки нужно обновить `derivedFrom` и заново утвердить выжимку.

## 7. Несколько тем в направлении и общие темы

Темы направления перечислены в `modules.json` → `lessons` в нужном порядке; поле `order` в метаданных задаёт порядок внутри направления. У каждой темы одно основное направление. Чтобы показать тему в другом направлении, добавьте его ID в `alsoInModules`, а связанные темы — в `relatedLessonIds`.

## 8. Новое направление

Добавить запись в конец `content/modules.json` с новым ID и номером. Счётчики на сайте пересчитываются автоматически. Первые 14 направлений и их порядок защищены проверкой.

## 9. Поиск

Поиск идёт по названию, ключевым словам, программе и опубликованному тексту выбранного варианта; черновики в рабочей сборке не индексируются. Синонимы и сокращения находятся в `content/synonyms.json`, одна группа — один набор взаимозаменяемых слов.
